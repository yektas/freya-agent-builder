# Builder failure diagnosis and first fix

Date: 2026-10-11. Scope: the first milestone of the competition feedback plan.

## Finding

The highest-impact confirmed defect is a mismatch between the builder's result-variable contract and Freya's API pre-action runtime. The builder promises tool-named result variables. Freya stores a pre-action result under the **node** name. The generated account-processing code therefore treats valid account data as missing and enters a conversation node that cannot record a promise.

This mechanism is visible in all 24 account-processing calls across the failed agent's three repetitions. It does not explain every failure. Identity-result interpretation, callback classification, and completion handling have independent defects that remain open.

## Implemented fix and verification

`src/workflow.ts` now adds an exception-guarded post-hook to API pre-actions. It exposes the current response as `<tool>_response.*`, matching the builder's existing contract and conversation-tool convention. It handles nested objects and array leaves, uses the observed string representation of booleans, clears old aliases before a later result, and preserves native node variables and authored post-hooks. Business rules and tool request schemas still come exclusively from the supplied inputs. Compilation remains local; registration remains separate.

The synthetic offline regression executes the actual compiled hook across a successful lookup and a later failed lookup. Before the fix it fails on the missing downstream item; after the fix it verifies result availability, stale-success removal, original-hook preservation, and source immutability. No recorded model-generated Python is executed locally.

The captured-boundary replay exposes the missing tool-named data for all 24 recorded account reads. This is a deterministic data-flow check, not a new benchmark score and not evidence that every failed conversation is repaired.

`pnpm run check` passes all 88 offline tests, formatting, lint, and both TypeScript checks. Inspector tests required loopback permission. A pre-existing completion polling race in `tests/ui-practice.test.ts` was corrected to wait for the completed result to be discovered before asserting its score; product behavior was unchanged by that test correction. The saved plan was formatted and its status updated to reflect this milestone.

The authorized smoke is one fresh A-only generation and one PUB-01 repetition with `in_words`, using the historical failed agent's model and API-default effort. The cap is $5, one generation, one case. The fresh candidate compiled successfully in 160,996 ms, with one model call and a $0.125636 estimated model cost. Its input and candidate-source hashes match the planned comparison. It again uses an account API pre-action and tool-named result checks, so the new compiler hook is present in the affected path.
