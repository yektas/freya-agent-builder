- Baseline source hash / commit: `c0d86dee558f9bc4931323adaef4912cf1b27d98` plus uncommitted work; the failing run is `experiments/generation/2026-10-11T14-57-07.011Z-4342e2b3-3ec8-407c-ae54-48cf659eafde`.

- Earliest consequential failure in the trace: v10 `trace.jsonl` records `+270.1s` at 45,273 draft characters, then `+300.1s  Failed: The operation was aborted due to timeout`. Its `model-draft.txt` is 51,202 characters and fails `JSON.parse`; the tail is mid-sentence inside the final `uncertainties` array while the preceding `workflowJson` value is already closed. Draft arrival was steady at roughly 6,000 characters per 30s, so an estimated 10–20 further seconds would have completed it. This is a deadline abort, not an API capacity failure: `run.json` records `usage: null` and no `max_output_tokens` reason.
- Evidence supporting the proposed mechanism: six recorded generations at the same output budget span 131s, 161s, 164s, 233s, 273s, and the 300s abort. Two of six exceed 233s against a 300s ceiling, leaving 27s between the slowest pass and the kill. v10 used the same model, effort, and strategy as the 273s pass, so the abort is not explained by configuration. The original 300s was chosen in `2026-10-10-generation-budget-fix.md` as an approximate doubling of 120s to accommodate the 12,000 → 24,000 token increase, not from measured latency.
- Regressions or missing cases: a longer worst-case wait doubles, and the total deadline has less room if generation and practice are both slow. The recorded practice run took 875s of scorer time, so 600s generation plus 875s practice plus compile, register, and export is roughly 1,525s, still inside 1,800s; three practice repetitions would exceed the total regardless of this change. Higher reasoning efforts than medium are untested at any deadline. No live run confirms that v10 would now complete.
- Uncertainty / suspected noise: the 10–20s completion estimate comes from the observed draft arrival rate, not from a completed run. One abort is a single observation. Generation latency varies with model load and reasoning usage, so 600s may be insufficient on a slower day rather than merely generous.
- Decision: repeat live generation before benchmark promotion.
- Reason: the deadline demonstrably terminated an incomplete-but-nearly-finished run, and the change removes that failure mode without altering the strategy or exceeding the total deadline. Promotion requires a live candidate that completes, compared against the recorded baseline rather than assumed.
